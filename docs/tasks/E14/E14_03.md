# E14_03 - Core: Dmg starts from the boot ROM
Role: CODE
Goal: Dmg::with_boot_rom starts at PC=$0000 with the boot ROM mapped.
Prerequisites: E14_02
Read (max 3 files, give line ranges): crates/puce8gb-core/src/machine.rs (grep first: pub fn new, reset, post-boot); docs/annexes/notes/10_boot_rom.md; docs/annexes/decisions.md (A_11)
Write only in: crates/puce8gb-core/src/machine.rs, crates/puce8gb-core/src/bus.rs, crates/puce8gb-core/src/cpu/
## Work
1. `pub fn with_boot_rom(rom: &[u8], boot: &[u8]) -> Result<Dmg, MachineError>` (reuse the error type of Dmg::new; add the variant `BadBootRom` if none fits). It builds the machine like Dmg::new, installs the boot ROM with expected length 256, and puts the CPU and I/O in the power-on state of note 10 (all values UNKNOWN in the note are 0, the LCD is off, PC = $0000, SP = $0000).
2. Dmg::reset: when a boot ROM is installed, call Bus::remap_boot and restart from the power-on state; without a boot ROM keep today's post-boot reset. Dmg::new is unchanged.
3. Tests with a synthetic boot ROM built in the test: 256 bytes of $00 (NOP) except: bytes $0000..=$0002 = C3 FC 00 (JP $00FC) and bytes $00FC..=$00FF = 3E 01 E0 50 (LD A,$01 then LDH ($50),A). The cartridge is a 32 KiB ROM-only image whose byte 0 is $AA. Run M-cycles (at most 40) until PC == $0100: this must happen; then boot_mapped is false, register A = $01 and read($0000) = $AA. A 255-byte boot ROM gives Err. Dmg::new on the same cartridge starts at PC = $0100 with the boot ROM not mapped (unchanged).
