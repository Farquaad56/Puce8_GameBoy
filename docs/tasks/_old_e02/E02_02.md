# E02_02 - Micro-op engine and NOP
Role: CODE
Goal: Cpu::tick() with an explicit instruction-boundary contract, executing NOP, plus a test helper.
Prerequisites: E02_01
Read (max 3 files, give line ranges): docs/annexes/notes/02a_cpu_core.md (1-150); docs/annexes/decisions.md (A_03)
Write only in: crates/puce8gb-core/src/cpu/
## Work
1. Read A_03 (grep -n -i "micro", "fetch", "boundary") and write the contract as a doc comment on `Cpu`: when the opcode fetch happens, when PC increments, what "instruction boundary" means. A_03 silent => UNKNOWN - to confirm, then task.py blocked.
2. Implement the engine per that contract: `Cpu::tick(&mut self, bus: &mut Bus)` = one bus access.
3. Add `pub(crate) fn at_boundary(&self) -> bool`: true exactly when the next tick starts a new instruction (no micro-op pending). It is the ONLY definition of "boundary" used by code and tests.
4. Fetch/decode plumbing. The CB prefix is a fetch of a second opcode byte (no CB execution yet).
5. Implement only NOP. Every other opcode consumes only its fetch(es) and does nothing else; no panic. Do NOT implement or test any other instruction here (they belong to E02_04 and later).
6. Test helper, `#[cfg(test)]` inside src/cpu/ (never under a tests/ directory): `exec(cpu, bus, &[u8]) -> u32` places the bytes in WRAM, sets PC, ticks at least once, then ticks until `at_boundary()`, and returns the tick count. A hang is an assert failure, never a silent cap.
7. Tests: NOP takes the cycles of note 02a and PC advances by 1; three NOPs in a row advance PC by 3 and take three times the NOP cycles; a CB prefix followed by one byte consumes two fetches; `at_boundary()` is true after reset; F low nibble stays 0.
