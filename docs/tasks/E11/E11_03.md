# E11_03 - Palette choice: settings and emulation thread
Role: CODE
Goal: The chosen palette is saved and applied to the machine, also after each ROM load.
Prerequisites: E11_02
Read (max 3 files, give line ranges): crates/puce8gb-desktop/src/emu.rs (grep first: Command, Load, machine); crates/puce8gb-desktop/src/settings.rs (grep first: Settings); crates/puce8gb-desktop/src/palettes.rs
Write only in: crates/puce8gb-desktop/src/palettes.rs, crates/puce8gb-desktop/src/settings.rs, crates/puce8gb-desktop/src/emu.rs, crates/puce8gb-desktop/src/main.rs
## Work
1. palettes.rs: `pub enum PaletteChoice { CoreDefault, Preset(usize), Custom([u32; 4]) }` (Default = CoreDefault, meaning: send nothing, the core keeps today's colors). `colors(&self) -> Option<[u32; 4]>` (None for CoreDefault; a Preset index out of range gives None). `to_text`/`from_text`: "default", the preset name, or "#RRGGBB,#RRGGBB,#RRGGBB,#RRGGBB"; an unknown text gives CoreDefault.
2. `pub fn pack_core(c: u32) -> P` converts 0xRRGGBB to the core pixel type P documented in E11_01 (read the Ppu code to see how a pixel is built). One test with a known color.
3. settings.rs: new key `palette` stored with PaletteChoice::to_text (same line format as `volume`).
4. emu.rs: new `Command::Palette([P; 4])`. The emulation thread keeps `palette: Option<[P; 4]>`, calls machine.set_dmg_palette when it receives the command, and re-applies it right after every successful Command::Load (a new Dmg is created there).
5. main.rs: App field `palette: PaletteChoice` from the loaded settings; send Command::Palette at startup and when it changes (only when colors() is Some).
6. Tests: to_text/from_text round trip for the 3 variants; "nope" gives CoreDefault; Preset(99).colors() is None; pack_core on one color.
