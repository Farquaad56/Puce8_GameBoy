Role: DOC
Goal: Write the note docs/annexes/notes/01_timing.md.
Prerequisites: D_01
Read (max 3 files, give line ranges): docs/annexes/seed/timing_constantes.md (hint sheet, ~35 lines, read whole) + refs/pandocs (grep + small ranges only)

## Work
0. Read the hint sheet. It lists the values to CHECK and the exact grep strings. It is NOT a source: never cite it in a Source line.
1. Locate sources in refs/pandocs: Specifications, Rendering, Timing, OAM DMA (names to find with ls/grep). Use grep -rn -i, then sed -n 'a,bp' on small ranges.
2. For each value of the hint sheet run its grep first, then sed -n 'a,bp' on the hit. Write the value only if pandocs shows it. Extract the facts for: master clock, T-cycle vs M-cycle, dots per line, lines per frame, cycles per frame, mode durations, refresh rate (DMG only, ignore double speed).
3. Write docs/annexes/notes/01_timing.md in French, paraphrased, using the fact format of AGENTS.md (Fait/Source/Fiabilite/Impact code/Statut).
4. Every number has a Source line (file#section). Missing info: Statut UNKNOWN - to confirm + line in open_questions.md.
5. Two sources disagree: Statut CONFLIT, both values, and name the test ROM that decides.
6. Max 150 lines. If it does not fit, keep what the code needs and list what you left out in the last lines.
## Rules
- Identifiers and comments in English, ASCII only. Zero invention: unknown => UNKNOWN - to confirm.
- Paraphrase only; at most a few quoted words per source.
- No Rust code in this task.
## Exit tests
- note is valid (<=150 lines, >=6 facts with Source and Statut, no TODO)
- non-regression: all earlier exit tests (run by `done`)
