# D_04 - Opcode table (generated, verified)
Role: DOC
Goal: Produce a verified SM83 opcode table as Rust const data.
Prerequisites: D_03
Read (max 3 files, give line ranges): refs/pandocs (grep for an opcode table / instruction set page)
Write only in: docs/annexes/code/, docs/annexes/notes/02c_cpu_opcodes_src.md
## Work
1. Search refs/pandocs for a full opcode table with bytes and cycles (grep -rn -i 'opcode' | head -20).
2. If no machine-readable table with length and cycles per opcode exists in the sources, ask the user ONE question: allow fetching a published opcode table (JSON) from the web, give the URL candidate and why.
3. Generate docs/annexes/code/opcodes.rs (ASCII only): `pub const OPCODES: [OpInfo; 256]` and `pub const CB_OPCODES: [OpInfo; 256]` with mnemonic, bytes, M-cycles (taken and not taken), flags Z N H C as text.
4. Illegal opcodes are marked explicitly (the table must say which ones, from the source).
5. Write a generator script docs/annexes/code/gen_opcodes.py if the table was produced by a script, so it can be re-run.
6. Verify: 256 entries in each table, illegal opcode count matches the source, spot-check 10 opcodes by hand against the source. Record the verification and source in docs/annexes/notes/02c_cpu_opcodes_src.md (Source/Fiabilite/Statut).
## Rules
- Identifiers and comments in English, ASCII only. Zero invention: unknown => UNKNOWN - to confirm.
- The generated file is later copied without reading. It must be correct now.
- Total cycles are not enough: record bytes and cycles; bus-access order is derived in E02.
## Exit tests
- file exists: docs/annexes/code/opcodes.rs
- 256 base entries
- generated file is ASCII
- source note valid
- non-regression: all earlier exit tests (run by `done`)
