# C01_32 - EI, DI, IME and interrupt dispatch, RETI
Role: CODE
Goal: Interrupt flow at instruction boundaries.
Prerequisites: C01_31
Read (max 3 files, give line ranges): docs/annexes/notes/02b_cpu_interrupts.md (grep first); docs/annexes/decisions.md (C_00 and A_03 consequences); docs/annexes/notes/02c_cpu_opcodes_src.md (grep EI, DI, RETI)
Write only in: crates/puce8gb-core/src/cpu/, crates/puce8gb-core/src/bus.rs
## Work
1. Add IME and the one-instruction EI delay to the engine state (decision C_00 + note 02b).
2. Implement EI, DI, RETI in `cpu/interrupt.rs` (`exec_interrupt_ops`) and wire one line in the dispatch chain.
3. Dispatch: at an instruction boundary (step 0, BEFORE the fetch) when IME=1 and (IE & IF & $1F) != 0: run the fixed entry sequence of note 02b (M-cycle count and bus accesses from the note), clear the served IF bit and IME, jump to the vector (priority: lowest bit first). Vector addresses come from note 02b.
4. IF is bus.io[0x0F], IE is $FFFF (see bus.rs). Add small helpers on Bus if needed (pending_interrupts()).
5. Tests: EI takes effect after the NEXT instruction; DI immediate; dispatch costs the documented M-cycles; priority; RETI = RET + IME; the pushed PC is the address of the next instruction.
