# C01_38 - blargg mem_timing 01 read_timing
Role: TEST
Goal: ROM "mem_timing 01 read_timing" prints Passed on the serial port.
Prerequisites: C01_37
Read (max 3 files, give line ranges): docs/annexes/notes/09_test_roms.md (grep first); docs/annexes/notes/02a_cpu_core.md (grep first); docs/annexes/decisions.md (section C_00)
Write only in: crates/puce8gb-core/src/, crates/puce8gb-cli/
## Work
1. Run: cargo run -q --release -p puce8gb-cli -- run "<rom>" --max-cycles 100000000 --expect-serial Passed   (rom path: see the check script).
2. Read the exit code and the printed text FIRST:
   - exit 4 = "UNIMPLEMENTED opcode": implement exactly that opcode in the group file where it belongs (unit test first, named c01_38_*), then rerun. It may belong to a later group task: that is fine, that task will only re-verify it.
   - exit 2 = timeout: rerun with `--trace 300000 2> trace.txt` (do not commit trace.txt) and read ONLY `tail -n 40 trace.txt`. Find the PC loop. If it is a CPU bug, fix it. If the ROM waits on LY / timer / serial / interrupt that does not exist yet: write the PC and the polled address in open_questions.md and call task.py blocked.
   - exit 1 = text mismatch: the ROM prints failing opcodes or a failure number. Copy that text into a comment of your reproduction test, find the cause in notes 02a/02c, fix in ONE module.
3. Never edit the ROM, never loosen --expect-serial, never add a ROM-specific hack.
## Rules
- Identifiers and comments in English, ASCII only. Zero invention: unknown => UNKNOWN - to confirm (open_questions.md).
- Name every unit test fn starting with `c01_38_` (the check filters on it).
- One tick = one M-cycle = AT MOST ONE bus access (decision C_00). Hardware arithmetic with wrapping_* only. No allocation in tick().
- A test is changed only if it contradicts the notes, never to make it pass. Never disable a test.
- cpu/registers.rs may only get ADDED helpers: its e02_01_ tests must keep passing.
- Timing ROMs check WHICH M-cycle touches the bus: fix the micro-step order inside the instruction, not just the totals. Cross-check with the cycle table of note 02c.
- FORBIDDEN: a test that ticks a REAL opcode of another group and expects it to be unimplemented (it breaks when that group is implemented and `done` replays old checks). To test the unimplemented path use `record_unimplemented` directly (core tests) or `Cpu::debug_set_unimplemented` (other crates). "Implement ONLY the LIST" means: write no code for other opcodes, not: write tests for them.

- non-regression: all earlier exit tests (run by `done`)
