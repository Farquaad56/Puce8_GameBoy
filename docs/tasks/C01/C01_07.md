# C01_07 - LD absolute, LDH and LD (C)
Role: CODE
Goal: Loads with an absolute or high-memory address.
Prerequisites: C01_06
Read (max 3 files, give line ranges): docs/annexes/notes/02a_cpu_core.md (grep first); docs/annexes/notes/02c_cpu_opcodes_src.md (grep the mnemonics); docs/annexes/decisions.md (section C_00)
Write only in: crates/puce8gb-core/src/cpu/
## Work
1. grep -n "## C_00" docs/annexes/decisions.md, then read only that section (engine contract: step, fetch, done(), latches).
2. For each mnemonic of the LIST below, grep -n -i it in note 02c: take the byte length and M-cycle count from the note. Write them in the tests as expected values, with the note name in a comment.
3. Implement in `cpu/load_abs.rs`: `impl Cpu { pub(super) fn exec_load_abs(&mut self, bus: &mut Bus) -> bool }`. It returns true when the current opcode belongs to this group (decide by opcode bit fields, see C_00) and false otherwise. Add ONE line for it in the dispatch chain of cpu/mod.rs.
4. Tests with the `exec` helper (C_00): per family check the tick count, register or memory result, flags, PC advance. Add at least one edge case (wrap-around or flag boundary).
5. Implement ONLY the LIST: write no code for other opcodes. Do NOT write any test about opcodes outside the LIST.
## LIST
LD A,(a16); LD (a16),A; LDH A,(a8); LDH (a8),A; LD A,(C); LD (C),A. Note the byte order of a16 (low byte first) and that $FF00+a8 wraps inside the high page.

- Identifiers and comments in English, ASCII only. Zero invention: unknown => UNKNOWN - to confirm (open_questions.md).

- One tick = one M-cycle = AT MOST ONE bus access (decision C_00). Hardware arithmetic with wrapping_* only. No allocation in tick().

"Implement ONLY the LIST" means: write no code for other opcodes, not: write tests for them.
