# C01_04 - CLI run command with exit codes and trace
Role: CODE
Goal: puce8gb-cli run <rom> works headless: serial text, exit codes, unimplemented-opcode report, trace.
Prerequisites: C01_03
Read (max 3 files, give line ranges): docs/annexes/notes/09_test_roms.md (grep first); crates/puce8gb-cli/src/main.rs (head -30)
Write only in: crates/puce8gb-cli/
## Work
1. Add `run <rom> [--max-cycles N] [--expect-serial TEXT] [--trace N]`. N = T-cycles (dots). Load with Dmg::new, loop `dmg.tick()`.
2. Every M-cycle (4 ticks) drain the serial buffer into a String and echo it on stdout as it arrives. Stop early when TEXT is contained in the output.
3. Exit codes: 0 expected text found (or no expectation and max-cycles reached); 1 run ended without the text (print the serial text); 2 timeout with an expectation not met; 3 load/read error; 4 the CPU recorded an unimplemented opcode: print `UNIMPLEMENTED opcode 0x%02X at PC=0x%04X` and stop. (If 1 and 2 would both apply, use 2 for max-cycles reached.)
4. `--trace N`: for the first N instructions print one line on STDERR at each instruction boundary: `A:xx F:xx B:xx C:xx D:xx E:xx H:xx L:xx SP:xxxx PC:xxxx PCMEM:xx,xx,xx,xx` (hex, bytes read with bus.peek). Use Cpu::at_boundary() and the public register fields.
5. Only the CLI touches files and stdout. Tests in the cli crate with a tiny synthetic ROM built in the test (header padded to $150): exit 3 for a missing file, exit 4 for a ROM whose first opcode is unimplemented, exit 0 for a ROM that sends one char on the serial port with the code bytes you write by hand.
