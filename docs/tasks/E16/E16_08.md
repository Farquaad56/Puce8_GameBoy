# E16_08 - Core: SGB color output of the game area
Role: CODE
Goal: The 160x144 game frame in SGB colors, using the attribute map.
Prerequisites: E16_07
Read (max 3 files, give line ranges): docs/annexes/notes/12b_sgb_graphics.md; crates/puce8gb-core/src/video/mod.rs (grep first: framebuffer, shade)
Write only in: crates/puce8gb-core/src/sgb/compose.rs, crates/puce8gb-core/src/sgb/mod.rs, crates/puce8gb-core/src/video/
## Work
1. Ppu keeps a shade buffer `shades: Vec<u8>` (23040 entries, values 0-3, the shade after BGP/OBP) written at the same place as the framebuffer, only when the machine is Sgb (allocate it only then; zero cost otherwise). It becomes part of the Sgb save state block (E16_19).
2. Sgb field `attr: [u8; 360]` (20 x 18 cells of 8x8 pixels, palette number 0-3, default 0).
3. `pub fn compose_game(shades: &[u8], attr: &[u8; 360], pal: &[[u16; 4]; 4]) -> Vec<P>` (P = the core pixel type, converted with rgb555_to_pixel from E15_09): pixel (x, y) uses palette attr[(y/8)*20 + x/8] and color index shades[y*160 + x].
4. Tests (exact): all shades 1, all attr 0, default palettes -> every pixel equals rgb555_to_pixel of 0x56B5 which is [173,173,173]; shade 3 with pal0 = [.., .., .., 0x7C00] -> [0,0,255]; attr cell (1,0) = 2 and pal2[1] = 0x001F with shades 1 -> pixel (8,0) is [255,0,0] while pixel (7,0) still uses palette 0; output length 23040.
