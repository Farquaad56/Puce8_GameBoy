# E16_06 - Core: MLT_REQ and joypad IDs
Role: CODE
Goal: Multiplayer request and the joypad ID read-back.
Prerequisites: E16_05
Read (max 3 files, give line ranges): docs/annexes/notes/12a_sgb_protocol.md; crates/puce8gb-core/src/input.rs (grep first: P1, read)
Write only in: crates/puce8gb-core/src/sgb/mod.rs, crates/puce8gb-core/src/input.rs, crates/puce8gb-core/src/bus.rs
## Work
1. MLT_REQ (id $11): byte 1 bits 0-1: 0 = one player, 1 = two players, 3 = four players (value 2: ignored, UNKNOWN - to confirm in the note).
2. With more than one player, reading $FF00 returns the ID values of the note and the current player advances as the note describes (when both select lines are written high). With one player the register reads as on a DMG.
3. Tests built from the note facts: (a) one player: P1 reads unchanged; (b) two players: the first read after the select lines go high returns the ID of player 1 in the low nibble, after the next pulse the ID of player 2, then back to player 1; (c) four players cycle 1-4; (d) after MLT_REQ with 0 the behaviour is back to one player.
