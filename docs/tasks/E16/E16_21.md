# E16_21 - SGB integration test with a synthetic ROM
Role: TEST
Goal: A hand-built ROM sends PAL01 and the game picture takes the SGB color.
Prerequisites: E16_20
Read (max 3 files, give line ranges): docs/annexes/notes/12a_sgb_protocol.md; docs/annexes/notes/12b_sgb_graphics.md
Write only in: crates/puce8gb-core/src/machine/, crates/puce8gb-core/src/machine.rs
## Work
1. Test-only code. Build a 32 KiB ROM-only image in the test: at $0100 `C3 50 01` (JP $0150); at $0150 a straight-line program: for every JOYP write of the encoding of note 12a for the PAL01 packet [$01, FF 7F, 1F 00, E0 03, 00 7C, 01 00, 02 00, 03 00, 00] emit `3E nn` (LD A,nn) then `E0 00` (LDH ($00),A); then `3E 91 E0 40` (LCDC = $91), `3E FF E0 47` (BGP = $FF), then `18 FE` (JR -2). Fix the header checksum like the E13_01 helper does.
2. Run the machine as Model::Sgb for 10 frames. Expected: every game pixel is shade 3 (BGP = $FF, tile data all zero) so with attribute map 0 the color is pal0[3] = 0x7C00 = [0,0,255]: sgb_frame pixel (48,40) = [0,0,255] and pixel (207,183) = [0,0,255].
3. Same ROM on Model::Dmg: pixel (0,0) of the normal frame equals the DMG shade-3 color (the packet is a harmless sequence of JOYP writes) and does not equal [0,0,255].
