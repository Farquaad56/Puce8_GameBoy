# E16_11 - Core: VRAM transfer capture
Role: CODE
Goal: The 4096-byte data of the *_TRN commands is captured from VRAM.
Prerequisites: E16_10
Read (max 3 files, give line ranges): docs/annexes/notes/12b_sgb_graphics.md; crates/puce8gb-core/src/video/mod.rs (grep first: lcdc, vram)
Write only in: crates/puce8gb-core/src/sgb/transfer.rs, crates/puce8gb-core/src/sgb/mod.rs, crates/puce8gb-core/src/bus.rs
## Work
1. `pub fn capture_vram_transfer(vram: &[u8], lcdc: u8) -> [u8; 4096]`: the 256 tiles (16 bytes each) of the tile data area selected by LCDC bit 4: bit 4 set -> bytes 0x0000..0x1000 of VRAM ($8000), clear -> 0x0800..0x1800 ($8800), bank 0 only.
2. Sgb field `pending_transfer: Option<u8>` (the command id waiting for its data). A *_TRN command (PAL_TRN $0B, ATTR_TRN $15, CHR_TRN $13, PCT_TRN $14, and the ignored SOU_TRN $09 and DATA_TRN $10 are NOT captured) sets it; the capture happens at the next start of VBlank (UNKNOWN - to confirm the real delay in the note: follow the note) and the data is handed to the command handler of that id (added by E16_12, E16_13, E16_15, E16_16; until then it is stored in `last_transfer: Option<(u8, Vec<u8>)>`).
3. Tests (exact): VRAM bytes filled with (index & 0xFF): with lcdc bit 4 set capture[0] = 0, capture[255] = 255, capture[256] = 0 and capture[4095] = 255; with bit 4 clear capture[0] = VRAM[0x0800] value = 0 (0x0800 & 0xFF = 0) so fill VRAM[i] = (i / 16) as u8 instead and check capture[0] = 128 (0x0800/16) and capture[16] = 129; a PAL_TRN packet followed by one VBlank stores last_transfer with id $0B and 4096 bytes; without VBlank nothing is stored.
