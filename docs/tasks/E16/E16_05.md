# E16_05 - Core: command assembler
Role: CODE
Goal: Multi-packet commands and the command table.
Prerequisites: E16_04
Read (max 3 files, give line ranges): docs/annexes/notes/12a_sgb_protocol.md
Write only in: crates/puce8gb-core/src/sgb/command.rs, crates/puce8gb-core/src/sgb/mod.rs (only `mod command;` and wiring)
## Work
1. `pub struct SgbCommand { pub id: u8, pub data: Vec<u8> }` (data = all packets concatenated, 16 * count bytes) and `pub struct CommandAssembler` with `pub fn push_packet(&mut self, p: [u8; 16]) -> Option<SgbCommand>`.
2. Header byte: id = byte0 >> 3, count = byte0 & 7. Count 0 is invalid: the packet is dropped and the assembler stays idle (UNKNOWN - to confirm in the note; follow the note if it says otherwise).
3. Constants for the command ids of note 12a (PAL01 = 0x00 ... OBJ_TRN = 0x18).
4. Wire it: Sgb owns a PacketReceiver and a CommandAssembler; every complete command goes to `fn execute(&mut self, cmd: SgbCommand)` which for now only stores it in `last_command: Option<SgbCommand>`.
5. Tests (exact): header $89 -> id $11 count 1; header $23 -> id 4 count 3; header $01 -> id 0 count 1; a count-3 command returns None, None, then Some with data length 48 and id 4; a count-1 command returns Some at once with data length 16; a header with count 0 returns None and the next valid packet still works.
