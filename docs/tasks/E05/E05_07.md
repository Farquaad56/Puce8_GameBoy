# E05_07 - Wire the mappers into the bus
Role: CODE
Goal: Replace the interim Bus ROM/SRAM shortcut by media::Mapper so MBC games can run.
Prerequisites: E05_06
Read (max 3 files, give line ranges): crates/puce8gb-core/src/bus.rs (the Bus struct, Bus::new, reset, read, write, peek, cart_result); crates/puce8gb-core/src/media/mapper.rs (public API only); crates/puce8gb-core/src/machine.rs (Dmg::new, battery_ram, load_battery_ram, the M-cycle block)
Write only in: crates/puce8gb-core/src/bus.rs, crates/puce8gb-core/src/machine.rs, crates/puce8gb-core/src/media/, crates/puce8gb-core/src/cpu/jump.rs
## Work
1. Bus gets a field `mapper: Mapper`, built in `Bus::new` with `Mapper::new(&rom, &header)`. If the header is unsupported or Mapper::new returns Err, fall back to `Mapper::RomOnly` (existing tests use zero-filled ROMs and must keep passing). Keep `Bus.rom` as the raw image (header checksum, tests).
2. Bus read/peek/write for $0000-$7FFF and $A000-$BFFF go through `mapper.read` / `mapper.write`. Remove the `sram` field, the SRAM allocation in `Bus::new`, and `sram.fill` in `reset`. `reset` rebuilds the mapper from `rom` (battery RAM is NOT kept across reset; the frontend reloads it with load_battery_ram). The mapper owns its own copy of the ROM, so a test that edits `bus.rom[..]` after `Bus::new` no longer changes what the CPU reads: rewrite such tests to build the ROM bytes first and then call `Bus::new(rom)` (known case: cpu/jump.rs `c01_10_jr_e8_wraps_past_bottom_of_memory`; change nothing else in that file).
3. Add `Mapper::ram_bytes(&self) -> &[u8]` (media/mapper.rs, one arm per variant, empty slice for RomOnly). `Bus::cart_result` reads the Blargg block from `mapper.ram_bytes()` instead of `sram`.
4. `Dmg::battery_ram()` becomes `Option<Vec<u8>>` and returns `bus.mapper.battery_payload()`; `Dmg::load_battery_ram` calls `bus.mapper.load_battery_payload` and maps `BatteryError` to `LoadError::NoBatteryRam` / `BatteryRamSizeMismatch`. Fix the callers in the CLI (compile errors tell which). The `e05_06_*` tests must be adapted to the new return type and must keep their meaning; do not delete any.
5. In the M-cycle block of `Dmg::tick`, call `bus.mapper.tick(4)` once per M-cycle (the RTC counts emulated dots, note 07b / A_05). A new test proves the MBC3 clock advances with Dmg::tick.
6. Tests named `e05_07_*`, at least: (a) MBC1 ROM bank switch visible through `bus.read(0x4000)` after `bus.write(0x2000, n)`; (b) MBC1 RAM stays closed ($FF read) until `write(0x0000, 0x0A)`, then writes/reads work at $A000; (c) ROM-only cart: $A000 reads $FF, writes ignored; (d) MBC5 9-bit bank reachable through the bus; (e) MBC3 RTC advances after N calls of Dmg::tick; (f) battery_ram round trip still works through the mapper; (g) unsupported cartridge type falls back to ROM-only without panic.
