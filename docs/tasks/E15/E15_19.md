# E15_19 - Savestate: Cgb block
Role: CODE
Goal: The Cgb model can be saved and loaded.
Prerequisites: E15_18
Read (max 3 files, give line ranges): docs/annexes/decisions.md (A_05, A_11, A_12); crates/puce8gb-core/src/machine/state.rs (grep first: extension, model); crates/puce8gb-core/src/bus/state.rs (grep first: write_state)
Write only in: crates/puce8gb-core/src/machine/, crates/puce8gb-core/src/bus/, crates/puce8gb-core/src/video/, crates/puce8gb-core/src/savestate.rs
## Work
1. After the extension block of E14_04, when the model byte is 1 (Cgb) write the Cgb block: compat flag, VBK, VRAM bank 1 (8192 bytes), SVBK and the 6 extra WRAM banks (24576 bytes: banks 2-7; bank 1 is the usual D000 area, adapt to your WRAM layout), BG palette RAM (64), OBJ palette RAM (64), BCPS, OCPS, OPRI, KEY1 bits, the HDMA registers and the HDMA active state (remaining blocks, source, destination, mode), RP, $FF72-$FF75, and the PPU attribute state added by E15_10-E15_12. Booleans are validated; ranges are validated; loads stay atomic.
2. Remove the guard of E15_04 (the Dmg and Cgb models are the only ones). VERSION stays 2: Dmg states do not change size.
3. Tests: Cgb round trip then 2 frames give the same framebuffer hash on both machines; a state saved on a Cgb machine loaded into a Dmg machine gives RomMismatch and the machine is unchanged; truncated Cgb state gives BadSize and the machine is unchanged; a corrupted compat byte (value 5) gives InvalidState; the Dmg state size equals the E14_04 size.
