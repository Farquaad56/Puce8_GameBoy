# E15_15 - Core: HDMA HBlank transfer
Role: CODE
Goal: One 16-byte block per HBlank, cancel and FF55 reads.
Prerequisites: E15_14
Read (max 3 files, give line ranges): crates/puce8gb-core/src/bus.rs (grep first: hdma); crates/puce8gb-core/src/video/mod.rs (grep first: mode 0, hblank); docs/annexes/notes/11c_cgb_speed_dma.md
Write only in: crates/puce8gb-core/src/bus.rs, crates/puce8gb-core/src/bus/, crates/puce8gb-core/src/video/, crates/puce8gb-core/src/machine.rs
## Work
1. $FF55 write with bit 7 = 1 arms an HBlank transfer of ((value & $7F) + 1) blocks. At the start of each HBlank (mode 0 of a visible line) one 16-byte block is copied and the CPU is stalled for that block (timing per the note). No block is copied during VBlank (lines 144-153) or while the LCD is off.
2. Reading $FF55 while active returns (remaining blocks - 1) with bit 7 = 0. A write with bit 7 = 0 while an HBlank transfer is active cancels it; FF55 then reads with bit 7 = 1 and the remaining count (per the note).
3. Tests: value $81 (2 blocks): after 1 HBlank 16 bytes are copied and FF55 reads $00; after the 2nd FF55 reads $FF; cancelling after 1 block leaves 16 bytes copied and FF55 bit 7 set; no copy while LY >= 144.
