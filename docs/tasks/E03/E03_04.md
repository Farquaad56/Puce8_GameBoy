## Hardware spec (fixed by the project)
This is a project decision: do NOT search the notes for what is written here and do NOT discuss it. If a line elsewhere contradicts this section, this section wins. If a note is longer than 150 lines, use grep -n on the keywords of the task and read only the matching ranges. Do not read more than 3 files.
- Sprite attributes (byte 3): bit 7 BG priority (1 = BG colors 1..3 are drawn over the sprite), bit 6 Y flip, bit 5 X flip, bit 4 palette (0 = OBP0, 1 = OBP1).
- Sprite color index 0 is transparent. LCDC bit 1 = 0 disables all sprites.
- Overlap: the sprite with the lowest X wins; on equal X the lowest OAM index wins.
- 8x16: the tile index has bit 0 ignored; the top half is tile (index and 0xFE), the bottom half is tile (index or 0x01). Y flip also swaps the two halves.
- A sprite covers screen pixels X - 8 .. X - 1.
## Work
1. Using `line_sprites` (E03_02), merge sprite pixels into the output stream: keep in each line buffer cell the color index, whether it comes from a sprite and which palette (a small struct, for example `PixelOut { color: u8, obj: bool, pal1: bool }`).
2. Flip, 8x16, priority and BG priority flag as in the spec. Do not change the mode 3 length in this task.
3. Tests: single sprite, two overlapping sprites (lower X wins, equal X lower OAM index wins), BG priority flag, X flip, Y flip, 8x16 with Y flip, color 0 transparent.
