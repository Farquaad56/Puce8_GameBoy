## Hardware spec (fixed by the project)
This is a project decision: do NOT search the notes for what is written here and do NOT discuss it. If a line elsewhere contradicts this section, this section wins. If a note is longer than 150 lines, use grep -n on the keywords of the task and read only the matching ranges. Do not read more than 3 files.
- Option `--frames N` (decimal): run N frames with run_frame, then stop with exit code 0. When it is given, --max-cycles and --expect-serial are ignored.
- Option `--dump-ppm FILE`: after the run, write the framebuffer as a binary PPM: the ASCII header `P6`, newline, `160 144`, newline, `255`, newline, then 160*144*3 bytes R,G,B (taken from the 0xAARRGGBB pixels).
- A missing or invalid value is a usage error: exit code 64, like the other options.
## Work
1. Add both options to the argument parser and to the args struct. Run in `run_rom`, not in `run_machine`.
2. Write the PPM writer as a small function that takes the framebuffer slice and a writer, so it can be unit tested.
3. Tests (names start with e03_16_): PPM header and total size (15 bytes of header for the 160x144 case plus 69120 bytes), pixel conversion of one known pixel, option parsing (valid, missing value, not a number).
