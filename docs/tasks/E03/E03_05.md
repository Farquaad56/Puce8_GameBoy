# E03_05 - Palettes and framebuffer

## Hardware spec (fixed by the project)
This is a project decision: do NOT search the notes for what is written here and do NOT discuss it. If a line elsewhere contradicts this section, this section wins. If a note is longer than 150 lines, use grep -n on the keywords of the task and read only the matching ranges. Do not read more than 3 files.
- Shade from a color index and a palette byte: shade = (palette >> (index * 2)) and 3.
- Sprite color index 0 is transparent whatever the palette says.
- Pixel format: u32 as 0xAARRGGBB with AA = 0xFF. Fixed table, neutral greys, documented in a code comment: shade 0 = 0xFFFFFFFF, shade 1 = 0xFFAAAAAA, shade 2 = 0xFF555555, shade 3 = 0xFF000000.
- LCD off: the framebuffer shows shade 0 everywhere (blank) as the note says.
## Work
1. Palette application per pixel using the PixelOut of E03_04: BGP for background, OBP0 or OBP1 for sprites.
2. Framebuffer of 160*144 u32 inside the Ppu; a finished visible line (end of mode 3) is written at row LY. `pub fn framebuffer(&self) -> &[u32]` and a forwarding method on Dmg.
3. LCD off fills the framebuffer with the shade 0 color.
4. Tests: BGP 0xE4 is the identity mapping, BGP 0x1B is reversed, sprite index 0 shows the background, a line lands at the right offset, LCD off gives a blank buffer. No floats.
