# E03_02 - OAM scan: sprite selection per line
Role: CODE
Goal: Mode 2 sprite selection. No pixels, no access blocking in this task.
Prerequisites: E03_09
Read (max 3 files, give line ranges): docs/annexes/notes/04a_video_regs.md (1-150); docs/annexes/notes/04b_video_render.md (1-150); docs/annexes/decisions.md (A_01)
Write only in: crates/puce8gb-core/src/video/, crates/puce8gb-core/src/bus.rs, crates/puce8gb-core/src/machine.rs
## Hardware spec (fixed by the project)
This is a project decision: do NOT search the notes for what is written here and do NOT discuss it. If a line elsewhere contradicts this section, this section wins. If a note is longer than 150 lines, use grep -n on the keywords of the task and read only the matching ranges. Do not read more than 3 files.
- OAM is 40 entries of 4 bytes at 0xFE00..0xFE9F: byte 0 = Y, byte 1 = X, byte 2 = tile, byte 3 = attributes.
- A sprite is on line LY when (LY + 16) >= Y and (LY + 16) < (Y + height), with height 8 or 16 from LCDC bit 2.
- At most 10 sprites per line, taken in OAM order. X is NOT used in the selection: a sprite with X = 0 or X >= 168 still counts in the limit.
## Work
1. During mode 2 (80 dots, 2 dots per entry or all at the end, the result must be the same) fill a list `line_sprites` of at most 10 OAM indexes for the current line.
2. Expose it with `pub(crate) fn line_sprites(&self) -> &[u8]` (OAM indexes in OAM order).
3. The scan reads OAM directly (the CPU access blocking is task E03_10).
4. Tests: 11 sprites on one line give the first 10 in OAM order, 8x8 and 8x16 boundaries (Y = 16 shows on lines 0..7 for 8x8 and 0..15 for 8x16, Y = 0 never shows), a sprite with X = 0 counts in the limit.
